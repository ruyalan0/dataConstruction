# 两个决策点观测替代整轮消息历史：可行性评估

方案在现有控制架构中可实现，已形成独立版本 `astra_io_250hz_obspair`。两时刻观测用于判断实际运动与接触变化，文字 memory 保留跨多个决策点的任务进度。它是输入策略变更，最终抓取表现仍需新的真实回合验证。

## 参考数据核对

`val.jsonl` 共 4,163 条、6 种任务。20 条首轮记录只有当前三图；4,143 条后续记录包含前后三路图，共 24,918 次图片引用。每条都是 system/user/assistant 三条消息，图像占位符与 images 数量相符。History 提供 available、duration_ms、previous_state，决策间隔为 60..500 ms；State 提供当前关节和夹爪信号，以及 last_gripper_command。参考数据本身没有文字 memory，输出为 arms + steps。

这些图片路径位于另一台机器的 `/share/workspace/...`，本机未找到原图，因此只核对了用户提供文件的结构和文本。图像内容与来源数据的物理正确性没有据此声称已验证。结构审计见 [audit/val-reference.json](audit/val-reference.json)。

## 与现有控制的对应

| 方面 | 新版本处理 |
|---|---|
| 历史输入 | 不再用 `self.previous` 回放旧 user、function_call、function_call_output 或推理 |
| 前一时刻 | 上一次已完成决策的**动作开始前观测**，不是前一个 4 ms 物理步 |
| 三路图 | head、left wrist、right wrist 都保存；不因只有单臂移动而省略另一个腕部图 |
| 当前输入 | 当前测得关节、腕部位姿、手指位置、当前命令、任务与剩余预算 |
| memory | 在 `observation.memory` 显式输入；模型仍输出 memory，执行后供下一轮使用 |
| 夹爪 | 保留真实手指测量（米）、命令回显和 desired_gripper_commands，分别标注，避免把命令当开度测量 |
| 时间 | `history.duration_ms = 实际控制步差 × 4`；保护截断按实际步数计算，零步拒绝时可为 0 |
| 控制输出 | 保留 control_arms 的 assessment、plan、memory、left、right、steps、settle 及 null hold 语义 |
| 执行器 | 延续 250 Hz 关节目标、25 Hz 任务时钟、8 秒 general_pickup 预算、插值和既有保护 |

没有直接套用参考数据的输出 schema。若还要以该 `val.jsonl` 原样训练并直接接入，需要额外统一 arms 包装、memory、settle、null 和夹爪目标语义；本次实现仅借鉴两个观测点的输入方式。输入测量保持原精度，没有跟随参考训练集将状态统一截断到四位小数。

## 保留与丢失的信息

两次关节测量、三视图和实际间隔能够描述动作后的实际状态，并支持比较物体相对手指和背景的变化。更早的阶段完成情况、失败原因假设、对象身份等信息需要通过 memory 压缩保留。

两时刻并不是整个过程的充分观测：短暂碰撞、夹爪中间滑动又恢复、保护触发原因和原计划目标都可能在两帧之间不可辨别。新输入按方案不提供上个调用及其完整反馈，因此模型不得把 memory 中的意图当成已完成事实。所有原始响应、执行反馈和逐周期跟踪仍保存在本地日志中用于审计，但不进入下一次模型输入。

本版本以全新策略会话启动。原来的 continuation_request 依赖旧问题结构，显式拒绝复用；同一请求的传输失败仍沿用原重试逻辑。新会话不会暗中拼入其他回合的历史。

## 验证与文本体积

离线测试覆盖实际请求组装、真实 policy 主循环、两帧状态和三路图片的顺序、memory 转移、提前中断、零步拒绝、禁止旧推理与调用回放、会话重置、原数值边界和四位小数规范化；同时复用原生控制队列、计时、回合边界和选卡测试。Swift 导出测试确认一条样本只含一个 user 输入并拒绝被改写的标签。

用已经完成的 250 Hz L20/L21/L22 的 39 次决策做离线格式预览：两个版本均引用 225 张次图片。旧 API 输入中的 user 文本及上次调用/反馈文本共 12,250,711 字节，新 user 文本约 663,354 字节，减少约 94.6%。统计排除 system、tools、图片字节和加密推理，不能换算为 API token、延时或费用降幅。明细见 [预览清单](examples/historical-input-preview/manifest.json)。

这些是旧轨迹的格式转换；没有用新输入重新请求模型或执行机器人，不能当成新版本成功轨迹或直接据此声称新版本仍然 3/3 成功。该结论需要以新版本入口另行实跑。

现有代码、原有 25 Hz/250 Hz 版本、脚本、发布代码和 `val.jsonl` 共 1,328 个文件做了 SHA-256 保护，另复核 4,711 个历史日志；校验由 [verify_originals.py](verify_originals.py) 执行。

## 后续真实运行

2026-10-20，完成独立的新版本 general_pickup L20/L21/L22 各一局：3/3 成功、均分 100，38 次模型决策，0 次原无效动作，L20 有 5 次夹爪保护中断。两时刻输入、observation.memory、实际 API 消息与训练标签均经过实跑日志核对。三局实际输入为 473,813 token，而此前完整历史版为 5,093,220；不同轨迹与决策数会影响这个整局对比，不能将其直接当作固定策略的频率或输入格式因果效应。完整结果、视频及真实 Swift 数据见 [实跑汇总](../../runs/general_pickup-io-250hz-obspair-3layouts-20261020-111723/SUMMARY.md)。上文 39 条预览仍然只是旧轨迹的离线格式转换，与此次新采集的 38 条样本分开保存。
