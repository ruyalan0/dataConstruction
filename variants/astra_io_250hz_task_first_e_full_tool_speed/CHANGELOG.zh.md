- 新增 `privileged_scene`，在决策点 RGB 对应的同一物理周期读取当前物体位姿、资产类别/描述、世界包围盒及可用功能/支撑点。采集不推进物理、不查询奖励、不规划或执行动作。
- 统一世界坐标、米制与 wxyz；处理非零环境原点、旋转和包围盒缩放。形变物体使用当前网格范围，缺失信息显式记录，不以初始布局或原点替代实时几何。非单位缩放的原生功能/支撑点暂不输出，避免该原生接口未应用实例缩放时产生错误坐标。
- 接通服务端、文件 IPC、策略上下文、模型输入构建和提示词。场景时间戳须与当前观测一致；不在仅用于历史的 RGB 采样点重复采集。
- 新协议 `observation_pair_joint_goal_privileged_v5`；运行器记录 `privileged_scene_enabled`。原始观测、`privileged-scene.jsonl`、实际请求和现有 Swift 导出均保留特权字段，没有隐式删改。

离线验证：79 项测试通过；父版本和发布版 644 个受保护文件哈希无变化。真实场景读取验证记录在 runs 下的 `privileged-scene-smoke-*` 目录，不调用模型 API。

## 2026-10-26：control_arms 内部同步轨迹与有界观察返回

按用户要求直接修改当前版本，不复制旧实现。模型仍只输出 `control_arms` 的目标关节角与夹爪；不恢复 steps、速度、时长字段，不新增工具，不自动插入试抬或恢复动作。

- 新增共享进度的五次多项式关节参考。执行层自动选时长，以 0.6 rad/s、3 rad/s² 限制每段参考；长目标沿相同关节路径截取部分，并预留参考停止后的测量窗口。这些是待实测调优的初始参数，不代表实际执行器速度/力。
- 单次观察区间最多 0.8 秒，部分段或区间结束返回 `observation_ready`，不声称最终到达；显式再次调用同一工具才继续目标。保留 0.5 秒停滞判据和 3 mm 夹爪保护。
- 新闭合命令的正常返回下限为 0.3 秒；静态保持默认 0.24 秒。夹爪稳定与物体保持仍分别处理，提示模型在下一次显式调用中小幅试抬。
- 高层目标仍每调用提交一次。逐周期日志及原生回放记录实际参考，并保存最终目标与段终点的独立误差；反馈客户端拒绝部分段伪报最终到达或物体保持。
- 输入结构沿用 `observation_pair_joint_goal_v4`、四位小数和 5s/4fps 历史。执行时钟升至 `native_joint_goal_v3`，执行模式升至 `synchronized_joint_goal_v3`，供运行器/导出器区分新旧控制数据。

验证：72 项离线测试通过，父版本/发布版 644 个受保护文件哈希无变化。本轮不调用真实模型或 Isaac；离线边界检查不能证明抓取或任务分数已恢复。

## 2026-10-25：加入最近 5 秒的 4fps 三路 RGB 历史

后续运行修复：多 GPU 并行启动时发现 RoboDojo 的 CuRobo 规划器 `DeviceCfg()` 默认固定为 `cuda:0`，导致选用 GPU 4/5/6 的三个进程仍在被其他服务占用的 GPU 0 初始化并发生 OOM。现在仅在当前服务进程的规划器模块内绑定 `--env-gpu`，启动时检查并记录实际双臂规划器设备。保留原生物理配置、控制实现和输入协议；失败的零模型调用启动记录保留。本项备份和验证见 [GPU 设备修复](../../runs/joint-goal-gpu-routing-20261025/REPORT.zh.md)。

- 在无 `steps` 的执行循环中加入按仿真时间采样的历史窗口：250 ms 网格向后对齐到首个 4 ms 物理周期，长动作中持续采样，保留每组三路 RGB 和真实时间戳。
- 模型输入按时间合并采样历史与前后两个决策点，保留端点实测状态、显式 memory 和同一时刻的精确决策图片；中间历史只包含 RGB。采样不触发新的模型决策。
- 输入协议升至 `observation_pair_joint_goal_v4`。启动器、策略、请求、工具记录和 Swift 导出统一核验 5s/4fps 配置；导出校验原始采样证据、图像顺序和源文件哈希。
- 保留 250 Hz 物理/状态检查、25 Hz 常规观测/任务/奖励、目标一次提交、原有到达/中断条件和四位小数输入输出。
- 完整备份、逐文件差异和离线验证见 [4fps 修改记录](../../runs/joint-goal-4fps-20261025/REPORT.zh.md)。本轮未运行真实模型或 Isaac 任务。

验证：64 项离线测试通过（本轮新增 12 项），包含长动作期间完整采样、5 秒窗口裁剪、端点合并与零运动返回、实际请求/IPC/Swift 导出一致性和篡改拒绝。三个 CLI 帮助检查通过，父版本和发布版 644 个受保护文件哈希无差异。

## 2026-10-24：目标一次提交，仿真逐周期推进

本轮在北京时间 10 月 23 日晚开始、24 日完成；备份和审阅产物位于 [joint-goal-latched-controller-20261023](../../runs/joint-goal-latched-controller-20261023/REPORT.zh.md)。修改 20 个文件，其中新增 3 个、修改已有 17 个。完整逐文件理由、前后哈希和补丁见该报告及其 `changes.json`、`changes.diff`。

1. 拆分 `set_joint_goal(action)` 和无动作参数的 `advance()`。目标校验、复制、关节/夹爪命令转换每个模型动作只做一次；其后推进物理并检查实测到达，不重新组装目标。提交目标本身不消耗仿真时间。
2. 原生队列仍逐周期消费控制帧。缓存的是最终关节目标和未经实测滤波的最终夹爪目标，每周期沿用原生 `MetaControl` 对夹爪的处理。不能改为重复使用上一次滤波后的夹爪中间值，否则可能改变夹爪闭合过程。
3. 辅助臂轨迹仍按物理周期取下一帧；不会在提交目标时提前消费，或把某一帧永久缓存。保留原生 PhysX 检查、动作记录、任务计时、奖励检查和交互回调。
4. 增加目标状态边界：未提交目标不能推进；原生队列有待执行帧时不能替换目标或额外推进；回合结束后不能提交/推进。目标先复制再校验，外部后续修改和失败的新目标都不会污染已保持的目标。提交时只读终止标志/时限，不额外调用会查询奖励的原生终止判定，避免改变任务检查时序。
5. 新增统一 `clocks.py`，区分物理频率、状态检查频率、相机频率、任务频率和模型决策时机。运行配置、请求审计、启动记录、工具记录和 Swift 清单统一使用这些字段，移除误导性的 `action_hz`、固定动作间隔和“每个动作一个物理周期”描述。服务参数改为 `--physics-hz 250`。
6. 执行时钟协议升级为 `native_joint_goal_v2`，执行模式升级为 `native_position_goal_v2`；输入结构仍是 `observation_pair_joint_goal_v2`。客户端、策略、请求构造器和导出器验证对应版本，防止把旧执行实现的数据标为本次实现。
7. 新增 `goals.jsonl`，每个已执行模型动作记录一次目标提交；完整反馈增加 `goal_submissions`，已执行动作为 1，执行前拒绝或零周期结束为 0。客户端及导出检查该计数。逐周期 `actions.jsonl`、跟踪数组和实际耗时继续保留；紧凑模型输入不额外加入目标提交计数。
8. 物理与实测检查仍为 250 Hz；相机、原生任务计时和奖励检查仍为 25 Hz；模型在执行返回后作下一次决策。关节容差 0.01 rad、稳定窗口 0.1 秒、停滞 0.5 秒、单次超时 10 秒、既有闭合夹爪变化 3 mm 的中断条件及原生执行器参数均未调整。

验证：47 项离线测试通过，包含本轮新增 11 项；9 个离线场景的逐周期队列帧、执行帧、测量、奖励检查、观测时点和最终反馈与优化前一致，比较时排除有意升级的执行元数据及新增提交计数。慢速样例仍执行 223 个物理周期，目标校验/转换次数从 223 次降为 1 次。三项 CLI 帮助检查通过；父版本和发布版 644 个受保护文件的哈希无差异。本轮真实 Astra 调用和 Isaac 仿真运行均为 0；这些结果验证实现与行为保留，不构成实际任务成功率或墙钟提速数据。
