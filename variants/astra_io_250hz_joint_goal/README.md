# 按关节目标执行，不由模型指定时长

独立于 `astra_io_250hz_obspair` 的实验版本。模型只使用 `control_arms` 输出目标关节角和夹爪命令；执行层自动计算双臂共享进度的关节参考轨迹与执行时长。每个模型动作只提交一次最终目标，不新增工具，也不在内部增加试抬、重抓或任务专用动作。

适配层通过 `set_joint_goal(action, trajectory=...)` 校验、复制和转换目标，通过无动作参数的 `advance()` 推进一个 4 ms 物理周期。每周期按同步轨迹更新手臂参考，夹爪保留原生基于实测开度的逐周期处理，辅助臂沿用原生轨迹。这里的“一次提交”指上层目标接口，逐周期参考不算新的工具调用。开发兼容入口 `take_action` 和未传轨迹的底层调用仍支持直接原生控制，模型执行路径始终提供同步轨迹。

当前采集面向可使用仿真真值的 Astra 教师。每个决策点 RGB 捕获完成后，在不推进物理的情况下读取顶层 `privileged_scene`：`schema/source/step`、世界坐标系及单位、环境原点和按语义标签索引的物体。每物体包含实时根位置/朝向、资产类别与最多三条资产描述、可用包围盒、功能点和支撑点。资产描述可能与当前渲染外观不同。包围盒提供世界坐标顶点、中心、轴对齐范围及尺寸；优先用实时位姿和缩放变换资产包围盒，衣物等形变物体使用当前网格范围。根原点不等于抓取点，包围盒不表示内部无碰撞。

物体姿态和点的坐标统一为世界米制，四元数顺序为 wxyz；显式处理环境原点。缺失几何记录在该物体的 `unavailable` 中，不造占位坐标。原生点接口不处理实例缩放，因此非单位缩放物体的功能/支撑点暂标为不可用；其包围盒仍正确处理缩放。本轮不读取奖励、规划目标关节或产生额外控制动作。

仅决策边界采集真值，按 `step` 与当前 RGB 对齐；4fps 历史采样继续只含 RGB，避免为每个历史帧重复读取场景。原始记录在 `seed-*/privileged-scene.jsonl`、决策点观测和实际模型请求中。IPC 和请求构建器拒绝时间戳不匹配或非有限数值。新输入协议名区分此前无特权输入的 v4。

本轮只加入特权字段。Swift 导出仍保留实际请求与标签，包含完整特权字段以及模型原始有效 `assessment/plan/memory`；没有生成删除特权字段的 Qwen 数据，没有改写文本、筛选可观察性或删样本。

验证：79 项离线测试通过。真实 Isaac 语言分类 L20 场景中，10 个对象的实时位姿和包围盒均已读到；生成模型输入时字段完整保留、时间戳匹配，仿真正常退出。本次模型调用和控制动作均为 0；该场景的资产没有功能/支撑点标注。见[真实输入样例](../../runs/privileged-scene-smoke-20261026-203512/example-model-input.json)和[验证记录](../../runs/privileged-scene-smoke-20261026-203512/validation.json)。

模型输出为 `assessment`、`plan`、`memory`、`left`、`right`。每个非空 arm 包含 `control: "joint"`、六个绝对关节角 `joints` 和 0..1 的 `gripper`。空 arm 或空 joints 保持动作开始时实测关节位置，空 gripper 保留上次命令。`steps`、`settle`、`duration`、`speed`、`phase` 均不属于输出协议。

底层沿用原 RoboDojo ARX X5 执行器的速度/力矩限制和物理参数。上层以 `s(u)=10u³−15u⁴+6u⁵` 生成共享进度的关节参考，参考在段首、段尾的速度和加速度均为零。按最大关节位移及参考速度/加速度上限自动选时长；长目标沿同一关节线截取一段，为参考减速和实测稳定留出时间。当前参考上限为 0.6 rad/s 和 3 rad/s²，属于未经真实接触任务调优的初始参数。

这些约束作用于每段参考，不能保证实际关节速度、接触力或避障安全；实际响应仍受负载、接触与底层执行器影响。各段从动作开始时的实测关节位置建立参考，共享关节进度不代表末端沿直线或实际双臂同时到达。

每周期读取实测关节和手指状态。参考结束后至少观察 0.1 秒，关节误差不超过 0.01 rad 且该窗口内关节/手指变化足够小时，才按到达或稳定返回。只有完整最终目标到达且夹爪到达，才返回 `target_reached`。夹爪稳定在非目标开度时返回 `gripper_settled_before_target`，不代表抓住物体。新闭合命令最早在 0.3 秒后正常返回；保护和原生终局可提前中断。模型必须用后续显式 `control_arms` 小幅试抬检查随动，执行器不会自动试抬。

单次最多推进 0.8 秒仿真；参考运动最多占 0.7 秒，剩余至少 0.1 秒保持段终点参考。部分轨迹完成或观察区间耗尽时返回 `observation_ready`，明确保留最终目标误差，模型查看后自行重发或修改目标。连续 0.5 秒无足够实测关节进展返回 `motion_stalled`；既有闭合夹爪变化超过 3 mm 立即中断。保护/停滞/回合结束可提前截断参考；即使正常观察返回，也不把参考停止解释为实际机构已静止。

阈值在 [joint-goal-controller.json](harness/configs/joint-goal-controller.json)。完整反馈记录参考轨迹、段终点、最终目标误差和逐周期参考跟踪误差；下一轮 `observation.last_motion` 提供状态、非空原因及最终/段终点误差，实际耗时见 `history.duration_ms`。

两臂目标都不变时，默认推进至少 0.24 秒观测窗口，可用于等待和原生完成检查；新闭合命令优先采用 0.3 秒下限。模型在接触附近仍应选择小幅中间关节目标。执行器不规划避障，也不以隐藏物体状态或任务阶段选择动作。现有 3 mm 夹爪保护保留，本轮不恢复旧腕部 35 mm 保护或改变其阈值。

输入包含最近 5 秒的 4fps 三路 RGB 历史、前后两个决策点的精确图像与实测状态，以及显式 memory。采样按仿真时间每 250 ms 进行一次，在下一个 4 ms 物理周期取图（偏差为 0 或 2 ms），不会累计舍入漂移。物理仿真和实测状态检查为 250 Hz；任务计时、奖励检查和常规相机采集仍为 25 Hz，另在 4fps 采样点取图，保留原生仿真时间预算。模型在执行返回后决策，没有固定调用频率。运行记录分别使用 `physics_hz`、`controller_check_hz`、`task_hz` 和 `observation_hz`，不再把 250 Hz 标成模型的动作频率。

长动作期间也持续采集 4fps 图像，按时间排序并与决策点图像合并；同一采样时刻与上一决策点重合时使用该决策点的精确图像。历史采样只含 RGB，不补造中间关节状态。上一决策点即使超过 5 秒仍保留；零运动返回保留前后两个端点。通常最多 22 组时刻、66 张图像。采样不触发模型调用，API 等待不推进仿真。原始采样索引保存在 `seed-*/visual-history.jsonl`。

每个实际执行的动作在 `goals.jsonl` 中只有一条最终目标提交记录，同时记录本次参考轨迹参数，反馈 `goal_submissions` 为 1；执行前拒绝的动作不提交目标，计数为 0。`actions.jsonl` 与原生回放记录逐周期实际送入底层的参考，完整跟踪反馈区分参考误差和最终目标误差，不能把这些行数当成模型动作数。`step`/`executed_steps` 保留为实测物理周期计数，模型不能指定它们。

当前模型输入协议为 `observation_pair_joint_goal_privileged_v5`。`budget` 只提供剩余仿真秒数和剩余模型调用数；`controller` 提供与决策相关的到达/中断阈值，完整时钟信息仍留在运行记录。`joint_semantics.joint_definitions` 合并两臂相同的静态关节定义，`arms` 保留世界几何和 FK 方向参考，实测关节角统一从 `observation.state` 读取。

模型输入和生效输出的结构化浮点数统一按 `ROUND_HALF_UP` 舍入到四位小数，JSON 使用固定四位数字，例如 `0.4000`、`0.0000`；数字仍为 JSON number。范围覆盖前后观测、关节角、位姿、FK 参考、夹爪、预算、阈值和动作误差；整数计数、布尔值、空值及文本中的数字不改写。原始测量先完成一致性验证和输入整理，再对发送副本舍入，底层物理、控制与到达判定保持完整精度。模型原始响应单独归档，执行参数和 Swift 标签使用同一份四位小数的生效输出。图像及任务完成规则保留。

技能文件的 YAML 描述和证据/来源说明保留在文件及哈希记录中，加载时只发送策略正文。该版本的技能已按关节目标接口清理；不会向模型发送旧局部 IK、固定 steps 或独立验证/回查工具的指令。四个只适用于旧控制模式的技能会在加载时排除，并记入 `action-interface.json`。

在项目根目录运行：

```bash
.venv-policy/bin/python -B variants/astra_io_250hz_joint_goal/run_local.py \
  --seed 20 --env-gpu 4 --episode-timeout 0
```

默认新建 `runs/general_pickup-io-250hz-joint-goal-<时间>/`。其他任务可传入 `--task` 和对应 `--task-config`；启动器记录并使用本版本的输出协议。不要将本协议与旧的固定 steps 数据混用。

独立布局可以在不同 GPU 上并行运行，每场使用不同 `--env-gpu` 和输出目录。CuRobo 规划器的设备也跟随该参数：原生 `DeviceCfg()` 默认写死为 `cuda:0`，本版本在当前服务进程的 RoboDojo 规划器模块内指定设备，避免多个进程挤占 GPU 0；不重映射 CUDA 可见设备。初始化后的双臂规划器设备记录在 `seed-*/planner-device.json`。物理参数和控制逻辑沿用原配置。

Swift 导出使用本版本 `export_swift.py`，标签保留实际生效的目标参数，不添加虚构时长。实测执行周期、秒数和中断原因留在原始反馈中。

当前输入协议为 `observation_pair_joint_goal_privileged_v5`，执行时钟协议为 `native_joint_goal_v3`，执行模式为 `synchronized_joint_goal_v3`。三个名称分别标记输入结构/精度、执行时钟语义和控制实现。运行器和 Swift 导出核验四位小数和 5s/4fps 元数据及采样证据；旧 v3 双端点输入不会被标为 v4；客户端核验执行协议和图像采样窗口。旧数据保留在归档中。服务端参数使用 `--physics-hz 250`。模型调用、工具 schema 和 Swift 文本输出使用同一份提示词合同。
